# SwipeX Backend

FastAPI backend for SwipeX, a swipe-based job discovery and personalized career
intelligence platform. The backend provides authentication and RBAC, jobs and
companies, swipes and applications, resumes and ATS analysis, recommendations,
notifications, analytics, administration, and WebSocket updates.

## Technology

- Python 3.12
- FastAPI and Uvicorn
- PostgreSQL 16 with SQLAlchemy 2.0 and Alembic
- Redis 7 for caching, rate limiting, and realtime features
- Local, MinIO, or other configured storage backends for resumes
- Local or remote AI adapters
- Console, SMTP, and push notification adapters

## Project layout

```text
app/
  api/v1/          HTTP and WebSocket routes
  core/            configuration, security, middleware, and rate limiting
  db/              database session and initialization helpers
  integrations/    AI, email, push, and storage adapters
  models/          SQLAlchemy models and enums
  repositories/    persistence access
  schemas/         Pydantic request and response schemas
  services/        application and domain services
  realtime/        WebSocket connection management
alembic/           database migrations
scripts/           operational scripts, including demo-data seeding
tests/             backend test suite
```

## Prerequisites

- Python 3.12 or later
- Docker Desktop with Docker Compose
- Git

PostgreSQL and Redis are only required locally when running the backend without
Docker Compose.

## Configuration

Create a local environment file from the template:

```powershell
Copy-Item .env.example .env
```

Review `.env` before starting the application. At minimum, set a strong
`SECRET_KEY` outside local development and configure the database, CORS,
storage, AI, email, and OAuth settings required by your environment. Never
commit `.env` or credentials to the repository.

The default development configuration uses:

- PostgreSQL on port `5432`
- PostgreSQL test database on port `5433`
- Redis on port `6379`
- Backend API on port `8000`
- MailHog, when enabled by your local setup, on port `8025`
- MinIO, when enabled by your local setup, on port `9001`

## Quickstart with Docker Compose

From this directory, start the development services:

```powershell
Copy-Item .env.example .env
docker compose -f docker-compose.dev.yml up --build
```

In a second terminal, apply the database migrations:

```powershell
docker compose -f docker-compose.dev.yml exec backend alembic upgrade head
```

To load demo data, run:

```powershell
docker compose -f docker-compose.dev.yml exec backend python -m app.db.init_db --seed
```

Stop the services with:

```powershell
docker compose -f docker-compose.dev.yml down
```

Add `-v` to `docker compose down` only when you intentionally want to remove
the PostgreSQL, test database, and storage volumes.

## Local development without Docker

Create and activate a virtual environment, then install the development
dependencies:

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
python -m pip install -r requirements-dev.txt
```

Start PostgreSQL and Redis separately, configure `.env`, apply migrations, and
run the API:

```powershell
alembic upgrade head
uvicorn app.main:app --reload --host 127.0.0.1 --port 8000
```

## Database migrations

Apply all migrations:

```powershell
alembic upgrade head
```

Create a new migration after changing the models:

```powershell
alembic revision --autogenerate -m "describe the schema change"
```

Review autogenerated migrations before applying them. To roll back one
migration:

```powershell
alembic downgrade -1
```

## Tests and code quality

The test suite expects the test database configured by `TEST_DATABASE_URL`.
With the Compose services running, execute:

```powershell
python -m pytest
```

Run the main formatting and linting checks:

```powershell
ruff check .
black --check .
```

To run tests with coverage:

```powershell
python -m pytest --cov=app --cov-report=term-missing
```

## API documentation and health checks

After starting the backend:

- Swagger UI: <http://localhost:8000/docs>
- ReDoc: <http://localhost:8000/redoc>
- OpenAPI schema: <http://localhost:8000/openapi.json>
- Liveness: <http://localhost:8000/api/v1/health>
- Readiness: <http://localhost:8000/api/v1/ready>

The API prefix defaults to `/api/v1` and can be changed with
`API_V1_PREFIX`.

## Seed data

Seeding is disabled by default. In development, use:

```powershell
python -m app.db.init_db --seed
```

The seed command creates demo users with known passwords. Do not enable
production seeding unless `ALLOW_PRODUCTION_SEED` is deliberately configured
and the security implications have been reviewed.
