# SwipeX Intern 3 — Gateway & Display Contract

This document specifies the frozen API contracts, Gateway routing specifications for **Intern 1**, and Frontend Dashboard display requirements for **Intern 4**.

---

## 1. Shared Gateway Integration Contract (For Intern 1)

The Intern 3 service runs as an independent backend service (`intern3-ai-service`) on port `8003` (or configured downstream service port). The shared Gateway managed by Intern 1 should forward the following routes directly to the Intern 3 service:

### Registered Routes:

1. **`POST /api/v1/resume/upload`**
   - **Method**: `POST`
   - **Content-Type**: `multipart/form-data`
   - **Query Parameters**: `user_id` (optional `string`)
   - **Description**: Upload candidate PDF resume, extract text, and return parsed skills.
   - **Upstream Target**: `http://intern3-ai-service:8003/api/v1/resume/upload`

2. **`GET /api/v1/resume/{resume_id}/ats-score?job_id={id}`**
   - **Method**: `GET`
   - **Path Parameters**: `resume_id` (`string`, required)
   - **Query Parameters**: `job_id` (`string`, required)
   - **Description**: Return rule-based ATS match score and missing skill keywords for the specified job.
   - **Upstream Target**: `http://intern3-ai-service:8003/api/v1/resume/{resume_id}/ats-score?job_id={id}`

3. **`GET /api/v1/recommendations?user_id={id}`**
   - **Method**: `GET`
   - **Query Parameters**: `user_id` (`string`, required), `resume_id` (optional `string`)
   - **Description**: Return recommended jobs sorted by match percentage (descending).
   - **Upstream Target**: `http://intern3-ai-service:8003/api/v1/recommendations?user_id={id}`

## 2. API Response Formats

### 2.1 Resume Upload
- **Endpoint**: `POST /api/v1/resume/upload`
- **HTTP Status**: `201 Created`
- **Response Payload**:
```json
{
  "resume_id": "c9b78e42-12a4-4f89-b1d6-847e099231f4",
  "parsed_skills": [
    "Docker",
    "Git",
    "Python",
    "SQL"
  ]
}
```

### 2.2 ATS Score Endpoint
- **Endpoint**: `GET /api/v1/resume/{resume_id}/ats-score?job_id=J004`
- **HTTP Status**: `200 OK`
- **Response Payload**:
```json
{
  "match_score": 40.0,
  "missing_keywords": [
    "Machine Learning",
    "TensorFlow",
    "PyTorch"
  ],
  "generated_by": "heuristic-v0"
}
```

### 2.3 Job Recommendations Endpoint
- **Endpoint**: `GET /api/v1/recommendations?user_id=U001`
- **HTTP Status**: `200 OK`
- **Response Payload**:
```json
[
  {
    "job_id": "J001",
    "match_percentage": 100.0,
    "generated_by": "heuristic-v0"
  },
  {
    "job_id": "J004",
    "match_percentage": 80.0,
    "generated_by": "heuristic-v0"
  },
  {
    "job_id": "J012",
    "match_percentage": 60.0,
    "generated_by": "heuristic-v0"
  }
]
```

## 3. Dashboard Display Contract (For Intern 4)

Intern 4 should consume these frozen response objects on the frontend dashboard without modifying backend response structures.

### 3.1 ATS Match Card Display
- **Match Score (`match_score`)**:
  - Render as a prominent visual gauge or badge (e.g. `40% Match`).
  - Color coding suggestion: `>= 70%` (Green), `40-69%` (Yellow/Orange), `< 40%` (Red).
- **Missing Keywords (`missing_keywords`)**:
  - Render missing required skills as actionable chips or pill tags under "Recommended Skills to Add".
  - If array is empty, display "No missing skills identified! Great match."
- **Generation Method Badge (`generated_by`)**:
  - Display subtle tag: `Generated by: heuristic-v0`.
  - Clarifies for users and reviewers that Milestone 1 uses rule-based keyword matching.

### 3.2 Job Recommendation Feed / Swipe Cards
- **Job Item Mapping**:
  - `job_id`: Used to bind candidate job card details from Intern 2's job feed.
  - `match_percentage`: Displayed directly on each job card banner (e.g., `80% Skill Overlap`).
- **Sorting**:
  - The API returns items pre-sorted in descending order of `match_percentage`.
  - Frontend can render cards in returned array sequence.
- **Generation Method Badge (`generated_by`)**:
  - Include tag `generated_by = "heuristic-v0"` in card details view or developer info popup.
