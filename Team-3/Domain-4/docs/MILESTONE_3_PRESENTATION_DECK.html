Integration Protocol

Resume API Integration Architecture

How Domain-4 securely communicates with the Resume Service.

POST /api/v1/resumes/upload Content-Type: multipart/form-data Body: { file: resume.pdf, label: "Senior Lead" } Response: 201 Created { "resume_id": "7b2e98...", "version_id": "3f1a42...", "original_filename": "resume.pdf", "is_active": true, "extraction_status": "pending" } POST /api/v1/resumes/{id}/parse Response: 200 OK { "parsed_status": "PARSED", "extracted_skills": ["Python", "React", "Docker"] }
Client-Side Normalization
• Unified Adapter: resumeService.js normalizes both legacy and M3 schemas.
• Defensive Fallbacks: Handles contract divergences (extracted_skills vs skills).
• Status Traps: Specifically captures 400 Bad Request (duplicate file hash), 401 Unauthorized, and 503 Gateway Unavailable with actionable user notifications.

Technical Scoring Rule
Zero Frontend Calculation: The frontend does NOT invent or compute ATS scores. All scores, percentiles, and thresholds are authored and computed by backend services.

Evaluation Provenance: Every result renders engine provenance (semantic-v1 or heuristic-v0) and calculation timestamp.
